# Router parity fixtures

Each `*.json` file is a routing snapshot (`{blocks, connections, width, height}`)
in the exact shape accepted by `routeWires` (RouterEngine.cpp) and produced by
`buildRoutingSnapshot` (route-worker.ts).

The committed goldens in `golden/*.routes.json` are generated by the **native**
router in deterministic mode and contain:

- `gridRoutes` — raw `computeWireRoutes` output (grid coords, pre-stub)
- `routes` — pixel points after `enforcePortStubs`

Two suites consume this corpus and must both stay green:

- C++: `nflow_router_tests` (doctest, `router_parity_tests.cpp`)
- TS: `modules/nflow_gui/src/ts/router/router.parity.spec.ts`

Together they prove the TS and native routers produce identical routes
(TS == golden == C++ by transitivity).

## Regenerating goldens

Only after an *intentional* routing behavior change:

```
cd modules/nflow_engine/tests/cpp
cmake -S . -B build-router -G "Visual Studio 18 2026" -A x64
cmake --build build-router --config Release --target nflow_router_tests
NFLOW_ROUTER_REGEN=1 ./build-router/Release/nflow_router_tests.exe
```

Then re-run both suites without the env var and commit the updated goldens in
the same commit as the behavior change.

## Fixture corpus

- `simple_pair` — one straight connection
- `fanout_shared_source` — one output port feeding three sinks (shared runs)
- `feedback_loop` — forward + feedback pair between two blocks
- `channel_two_nets` — two nets forced through a corridor between blockers
- `dense_grid` — 4×4 chained blocks (snake)
- `crossing_ladder` — four sources wired to swapped sinks (max crossings)

Synthetic fixtures are self-contained (edit or add fixture JSONs directly;
grid-aligned coordinates, GRID_SIZE = 10 px).

The `example_*.json` fixtures are CONVERTED from real diagrams in
`modules/nflow_blocks/examples/*.nflow` by the catalog-aware converter spec
`modules/nflow_gui/src/ts/render/router-fixture-converter.spec.ts`: it
instantiates the real editor (block libraries included) in jsdom, so block
width/height/ports come from the actual catalog. Without env vars the spec is
a DRIFT GUARD — it fails when catalog geometry no longer matches the
committed fixtures. To refresh after an intentional catalog change:

```
cd modules/nflow_gui
NFLOW_FIXTURES_REGEN=1 npx vitest run src/ts/render/router-fixture-converter.spec.ts
```

then regenerate the goldens (NFLOW_ROUTER_REGEN=1, above) and re-run both
parity suites.

## Scalability benchmark (router_bench_tests.cpp)

Full `routeWires` wall time on synthetic snake diagrams, MSVC Release,
Windows 11 workstation (2026-08-03, refineIterations=2 default):

| Blocks | Wires | Uncapped padding | Padding cap | Buffer reuse | + window & incr. near-map |
|---|---|---|---|---|---|
| 100 | 102 | 4.1 s | 1.0 s | 0.6 s | **0.51 s** |
| 200 | 202 | 25.6 s | 3.6 s | 1.5 s | **1.03 s** |
| 400 | 406 | 58.0 s | 10.6 s | 4.4 s | **2.28 s** |

History: `searchPadding` used to be `max(20, max(width,height)/GRID + 5)` —
for a 2700 px canvas that padded the search grid by ±275 CELLS per side,
inflating the A* state space ~10×. It is now capped at 40 cells
(`computeSearchPadding`, mirrored in pathfinder.ts and RouterEngine.cpp);
routes were unaffected (goldens unchanged — optimal detours never wander
that far outside the bounding box).

A* buffer reuse: a single StateArrays scratch instance (and hysteresis
bonus array) is shared by every planSingleConnection call of a routing pass
(main loop, pinned legs, refine) — assign()/fill() reuse the capacity
instead of reallocating ten stateCount-sized arrays per connection.
Behavior is identical (golden corpus unchanged).

Bounded-region search: each connection's A* runs on the endpoints' window
(bbox ± 40 cells, clamped to the global bounds) instead of the whole
diagram — state buffers scale with the window; a failed bounded search
falls back to the full bounds. Near-maps stay indexed on the global bounds.

Incremental wire-near map: one shared map per routing pass, marked
incrementally as each wire lands (codes only strengthen) instead of an
O(diagram area) rebuild per connection; rip-up waves rebuild it.

Visibility-graph rewrite (R4b): retired. After padding cap + buffer reuse +
bounded windows + the incremental near-map, routing scales near-linearly
with wire count at interactive sizes (~5 ms/wire at the 400-block scale).
